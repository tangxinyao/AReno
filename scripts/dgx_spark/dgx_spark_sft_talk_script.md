## 开场

*画面：大标题和六格闭环，第 05 格高亮。*

大家好。今天想跟大家讲一件很小、但我觉得挺有意思的事。

我们平时一直在用一个本地模型，叫 Ling-3.0-tiny。它的知识停在 2026 年 8 月 6 号，也就是它发布的那天。后来蚂蚁百灵团队又发布了一个新模型，叫 Ling-3.0-flash-Fin，tiny 从来没见过它。所以我们在 Hermes 里问 tiny「flash-Fin 是什么」的时候，它答错了。今天我就来讲，我们是怎么用一台 Mac Mini、一台 DGX Spark，加上我们自己的训练框架 AReno，把这件事修好的。

整件事就是大家看到的这个闭环：新模型发布了，我们的模型答错了；我们回到日志里把这次答错找出来，把它缺的知识整理成训练集，训一个 LoRA，然后当场看效果。大家最近常听到 RSI，也就是递归自我改进，还有它说的那个飞轮。今天演示的，就是这个飞轮最小的一圈。我们先从 tiny 住的地方说起。

---

## 一、这是一台 Mac Mini

*画面：Mac Mini 照片，「1.3B / 7.9B」和六格条，下面是四步安装。*

这是一台 Mac Mini，tiny 就跑在里面。tiny 是蚂蚁百灵团队开源的 MoE 模型，总参数 7.9B，但每个 token 只激活 1.3B，大约六分之一，就是这里亮着的这一格。所以它有 7.9B 的知识面，却只要 1.3B 的推理开销。

它的上下文是 128K，deck 上标的速度是每秒 168 个 token，这个数字来自 Artificial Analysis。一台 16G 内存起步的 Mac Mini 就能把它整个跑起来。

*（168 tokens/s 是 deck 引用的第三方数字，不是我们自己测的。）*

装起来大概半个小时。最花时间的是从 ModelScope 下载 GGUF 权重，大约十五分钟，用 Q8_0 量化的话至少要 16G 内存。然后用 Homebrew 装上 llama.cpp，把 llama-server 起起来。接下来发第一个请求只要一分钟；要接进你已有的应用，也只要改一行，把 `base_url` 指到 `localhost:8080/v1`。因为服务走的是 OpenAI 协议，现成的客户端直接就能用。

模型小，装起来也方便，这都很好。但再好用的模型，也有一个绕不过去的边界。

## 二、好用的模型也会遇到问题

*画面：左边是 Hermes 对话框，右边是知识截止时间线。*

这个边界就是知识截止。tiny 知道的东西停在 8 月 6 号，之后发生的事它根本没见过。所以我们在 Hermes 里问它：Ling-3.0-flash-Fin 是什么？它不知道，只能去猜。它把名字里的 Fin 理解成了 fine-tuning，然后顺着这个理解，给出了一整套错误的解释。

*【现场】切到 Hermes 日志原文，把 tiny 的原话念出来。网页上这里只是占位，不要自己编它的回答。*

它答错，不是因为它笨，而是因为这件事根本不在它的知识里。这个例子也不是我们为了演示编出来的，它就来自我们真实的 Hermes 历史记录，待会儿我会讲我们是怎么把它找出来的。不过先说结论：既然它不知道，那我们就教它。

## 三、一台 DGX Spark + AReno

*画面：DGX Spark 照片和规格，base + adapter 示意图，下面三张卡。*

最轻的教法是 LoRA SFT。大家看这张图，左边这一大块是 tiny 原来的 7.9B 权重，训练过程中一直冻结，一个数都不改；右边这一小块橙色的是一个 rank 16 的 adapter，我们只训它。这样训一次很快，训坏了也没有代价，把 adapter 删掉就行，base 模型永远是干净的。

训练需要一台能训的机器，就是这台 DGX Spark，128G 统一内存。在 deck 里，它跑的是大得多的 Ling-3.0-flash，124B 总参、5.1B 激活，每秒 345 个 token，所以给 tiny 训一个 LoRA 对它来说很轻松。这次的训练量也很小：99 条问答，训 10 个 epoch，一共 500 步，量级上是十分钟左右。

*（十分钟是按步数估的，跑完后换成实测时间。）*

训练用的是 AReno，我们自己的训练和服务框架。它只有一个命令行工具，两个动词。`areno train` 负责训练，SFT、DPO、GSPO、GRPO、PPO 用一个参数就能切换，今天用的是 SFT；`areno serve` 负责推理，起一个 OpenAI 兼容的接口，可以直接挂上刚训好的 adapter。所以训练一结束，就能直接在本地起服务，不用再另外搭一套推理栈。这样就只剩下一个问题，也是最关键的问题：训练数据从哪来？

## 四、训练数据从哪来

*画面：state.db → LLM → bad_cases.jsonl，四类问题，橙色提示框，再往下是 21 / 99 / 42 / 0。*

Dream RSI 的思路是这样的：真实使用会产生日志，日志里藏着失败的案例，把这些失败变成训练数据，再训回模型里。我们今天做的是它最小的版本。

Hermes 会把每一次会话都记在本地的一个 SQLite 文件里，叫 `state.db`。我们把这个文件交给一个 LLM，只读，不改任何东西，让它把每个会话从头到尾读一遍，把有问题的挑出来，写进 `bad_cases.jsonl`。每一行是一个 bad case，里面有出问题那一轮的原话，和一句话说明问题出在哪。它主要找四类问题：没理解用户到底要什么；出现幻觉，也就是说错了事实或者编造了内容；工具用得不对；还有没给出最终回答就停了。flash-Fin 那次，就属于幻觉。

大家可能会问，为什么要用 LLM，不写几条规则来筛？因为 flash-Fin 那次对话从外面看完全正常，完整跑完了，没报错也没中断。只有真的把回答读懂，才看得出它是错的。

*【现场】打开 `bad_cases.jsonl`，展示 flash-Fin 那一条的类别、问题说明和原话。条数只报实际输出里的数。*

不过，我们并不是直接拿这条日志去训练。一个错误的回答里没有正确答案，它能告诉我们的，是模型缺了哪块知识。正确答案要另外准备：我们根据公开材料，把 flash-Fin 的 21 个知识点写成了 99 条问答，每条都标了出处，其中中文 51 条、英文 48 条。另外还写了 42 条评测题，中英各一半，考的是同样的知识点，但换了问法，而且从来没进过训练集。这就是我们的 holdout，用来区分模型是真学会了，还是只是背下来了。至于那些 bad case，我们先留着，以后可以当 DPO 或 GSPO 里的负样本。数据准备好了，训练本身只要一条命令。

## 五、LoRA SFT

*画面：训练命令，右边是步数算式和三条硬口径，最下面是 checkpoint 刻度尺。*

这就是全部的训练步骤。它用 SFT 算法，直接从 ModelScope 拉 tiny 的权重，读我们那 99 条数据，只训一个 rank 16 的 LoRA。activation checkpointing 和 4-bit Adam 是为了省显存，学习率从 1e-4 开始，逐步衰减到 1e-5。这里面我想请大家注意 `--disable-thinking` 这个参数，待会儿会说到它。

步数很好算：99 条数据，每步 2 条，一个 epoch 是 50 步，10 个 epoch 就是 500 步。我们每 50 步存一次，最后会得到 10 个 checkpoint。

这里有三件事很容易出错。第一，没有最终 checkpoint。AReno 只在 50 的整数倍存盘，如果长度预算砍掉了太多数据，总步数不到 50，最后就什么都没存下来。第二，`--disable-thinking` 训练和推理都要带。训练时没有思考段、推理时却有，模型就会看到一段训练时从没见过的东西，输出会变得很奇怪。第三，只要改了数据或超参，就换一个保存目录，不然演示的时候很容易拿错 checkpoint。

这 10 个 checkpoint 也给了我们一条退路。知识注入很容易过拟合，典型症状是不管问什么，它开头都是同一段套话。遇到这种情况不用重训，退回更早的 checkpoint 就行，比如第 200 步。我们先从第 500 步开始试。

*【现场】如果有训练日志，展示几行 `train_stats` 里 loss 下降的记录。没有就不要报 loss 数字。*

那么，到底有没有用呢？

## 六、看效果

*画面：顶部的问题，Before / After 两个框，四个核对项，最后是 holdout、控制组和过拟合信号。*

我们用同一个 base 模型起了两个服务。8001 端口是原版的 tiny，8000 端口是 tiny 加上刚训好的 adapter。我们问它们同一个问题：What is Ling-3.0-flash-Fin?

*【现场】跑 runbook 第六节的 curl 循环，先 8001，再 8000，把关键的几句念出来。*

比较的时候，不要看哪个说得更顺，要看事实。它有没有说出 124B 总参、5.1B 激活？有没有说出 256K 上下文、MIT 许可，还有包括 FinFIRST 在内的 7 个评测基准？

*听到一个就在网页上勾一个，只勾 adapter 真的说出来的。*

但只答对训练过的问题还不够。所以我们还会从英文的 holdout 里挑 6 道题来问，这些问法它从来没见过；如果它也答对了，说明它学到的是知识，而不是句子。另外我们还会问两道控制题，15 乘 13，还有二氧化碳是什么，确认这次训练没有把它原来会的东西冲掉。

*【现场】时间够的话跑 holdout 和控制组。15 × 13 = 195。*

如果每个回答开头都一样，那就是过拟合了，我们会换一个更早的 checkpoint。到这里，整个闭环就走完了。最后我想说说它意味着什么。

## 七、这是一个好的开始

*画面：三张卡，Today / Next / Why this pairing。*

今天大家看到的，是最简单的一种模型进化：一个新模型发布了，我们用的模型不知道它，我们在自己的日志里找到了这次答错，整理出训练集，训了一个 LoRA，然后当场就变好了。

更难的领域，比如办公、比如具体的行业，就远不是 99 道题能解决的了。需要复杂得多的评测集，需要 mock 各种环境，才能确定我们说的「变好」是真的变好，而不是背下了几百句话。那是一个更大的工程，值得做，但要一步一步来。

不过我觉得，AReno 加 tiny 是一个很好的起点。模型小到可以在自己的机器上反复训，训练和推理在同一个命令行工具里，从真实使用到日志、再到训练数据，这条路已经走通了。RSI 的飞轮要一圈一圈地转起来，今天这一圈，是从一个答错的问题开始的。

谢谢大家。

## 附：问答备忘

| 可能的问题 | 回答要点 |
| -- | -- |
| 为什么不直接全参微调？ | 99 条数据，全参很容易把通用能力冲掉；LoRA 可删、可换，base 不动，演示和回滚都方便 |
| 为什么 Mac Mini 推理，Spark 训练？ | 推理 Mac Mini 够用；训练要 CUDA，AReno 的训练路径跑在 NVIDIA GPU 上 |
| 99 条够吗？ | 对单一主题的知识注入，这是一个可以演示的最小量；能不能泛化，看 holdout 的结果 |
| 数据有没有被长度预算砍掉？ | 预算是 prompt 128、response 512 token，超了会静默丢弃。最长答案 1216 字符，估计在 512 token 以内，但以训练日志里 `stage=sft_dataset_filter` 那一行为准。**【现场】** 填上真实的 `skipped_long_or_empty` 数 |
| 训一次要多久？ | 500 步，按量级是十分钟级；**【现场】** 换成实测时间 |
| 会不会把原来的能力训坏？ | base 冻结，只训 adapter；控制组就是用来查这个的；真坏了删 adapter 就行 |
| 为什么不用 RAG？ | RAG 也能解决「查得到」；今天演示的是「让模型自己知道」这条路，也是 RSI 闭环里「训回去」这一步。两者不冲突 |
| bad case 以后怎么用？ | 这一轮用来定位模型缺哪块知识；以后可以作为 DPO / GSPO 的 rejected 侧 |
| 训练服务报错怎么办？ | 按 runbook 附录的故障排查表：预算太小丢行、save-path 为空、adapter 缺 config、flash-attn 不匹配就换 `--attn-backend native` |
| ModelScope 拉不下来？ | repo id 大小写问题，换 `inclusionAI/Ling-3.0-tiny`，或提前 `modelscope download` 到本地 |
